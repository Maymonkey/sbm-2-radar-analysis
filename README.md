# SBM-2 Radar Analysis

ระบบทดลองติดตาม **กลุ่ม echo จากเรดาร์ฝนหลวงสัตหีบ** รอบ SBM-2 และประมาณเวลาที่รูปร่างกลุ่ม echo จะเคลื่อนเข้าพื้นที่เป้าหมาย ใช้ Python + GitHub Actions ไม่มีบริการ AI หรือ server ภายนอกสำหรับคำนวณ

## ขอบเขต

- SBM-2: **13.071556, 100.777556**
- สถานีสัตหีบ: **12.649027238747239, 100.96279558826618**
- พื้นที่ตรวจรอบ SBM-2: **รัศมี 100 กม.**
- พื้นที่เป้าหมาย: **สี่เหลี่ยม 5 × 5 กม.** (ไม่ใช่รัศมี 5 กม.)
- ใช้ **10 ภาพล่าสุดที่หาได้** รวมภาพที่เก็บจากรอบก่อน ข้ามวันที่ API ตัดรายการที่ 00:00 ICT
- เวลาในชื่อไฟล์เป็น UTC; เวลาในผลวิเคราะห์ทั้งหมดเป็น **ICT / UTC+07:00**
- คาดการณ์การเคลื่อนที่สูงสุด **60 นาที** นับจากเวลาภาพล่าสุด

**สถานะ:** pipeline มี regression tests และประวัติการติดตามที่ตรวจย้อนหลังได้ แต่แบบจำลองยังเป็น **experimental** และยังไม่ผ่านการวัดความแม่นยำเทียบฝนจริงที่ SBM-2 จึงยังไม่ใช่ระบบเตือนภัยทางทะเลที่รับรองแล้ว ส่วนสรุป API ถูกจัดรูปแบบไว้แล้ว; GitHub Pages จะเผยแพร่เมื่อเปิดใช้งานตามขั้นตอนด้านล่าง

## วิธีรันบน GitHub

1. เปิด **Actions → Check and download Royal Rain radar images**
2. เลือก **Run workflow → main → Run workflow**
3. เมื่อสำเร็จ เปิดรายการรันนั้นแล้วดาวน์โหลด artifact ชื่อ `sattahip-radar-latest-10-<run_id>-<attempt>`
4. อ่าน `latest-status.json` และ `diagnostic-cloud-shapes.png` ก่อน หากต้องตรวจเส้นทาง ให้เปิด `cloud-track-observations.csv`

Workflow จะรันตามตารางนาที `:02, :08, :14, ... :56` ของทุกชั่วโมง (cron ตั้งเป็น UTC แต่ค่านาทีตรงกับ ICT) และรันเมื่อโค้ดวิเคราะห์/config เปลี่ยนบน `main`; มี Tests แยกสำหรับทุก push/PR ตารางเป็นเป้าหมายการเรียก ไม่ใช่การรับประกันว่า GitHub Actions จะเริ่มตรงนาทีนั้นเสมอ

### เปิดลิงก์ API เดียวผ่าน GitHub Pages

workflow เตรียม JSON ไว้ที่ `public/api/latest-status.json` และจะ deploy หลังวิเคราะห์สำเร็จเมื่อ repository variable `PUBLISH_PAGES` มีค่า `true` เท่านั้น ก่อนเปิดใช้ ให้ไปที่ **Settings → Pages → Build and deployment → Source: GitHub Actions** แล้วสร้าง variable ชื่อนี้ใน **Settings → Secrets and variables → Actions → Variables** จากนั้นรัน workflow หนึ่งครั้ง ลิงก์ API คือ:

`https://maymonkey.github.io/sbm-2-radar-analysis/api/latest-status.json`

Repository นี้เป็น private; GitHub Pages ใช้กับ private repository ได้เฉพาะแผนที่รองรับ และ site อาจเปิดให้คนทั่วไปเข้าถึงได้ อย่าเปลี่ยน visibility ของ repository เพื่อให้ API ใช้งานได้โดยไม่ตรวจผลกระทบก่อน ตัว JSON มี `valid_until_ict`; client ต้องเทียบเวลาปัจจุบันกับค่านี้ทุกครั้ง เพราะไฟล์ JSON แบบ static ไม่สามารถเปลี่ยนตัวเองเป็น stale หลังเผยแพร่ได้

## ไฟล์ผลลัพธ์

| ไฟล์ | ใช้ดูอะไร |
|---|---|
| `latest-status.json` | สถานะภาพล่าสุด คุณภาพข้อมูล echo ในช่องเป้าหมาย และกลุ่ม inbound ภายใน 60 นาที |
| `cloud-tracks.csv` | สรุปแต่ละ track; `is_latest_scan` แยกกลุ่มปัจจุบันจากกลุ่มที่จบแล้ว |
| `cloud-track-observations.csv` | หนึ่งแถวต่อกลุ่มต่อภาพ: เวลา พิกัด pixel/lat-lon โดยประมาณ dBZ ระยะ ทิศ ความเร็ว และข้อมูลการจับคู่ |
| `dbz-timeseries.csv` | จำนวน pixel ที่ผ่านเกณฑ์ในวง 100 กม. และช่อง 5 × 5 กม. ของแต่ละภาพ |
| `diagnostic-cloud-shapes.png` | ขอบกลุ่มปัจจุบันสีฟ้า; กลุ่ม inbound/ทับเป้าหมายที่ข้อมูลผ่านเกณฑ์สีชมพู พร้อมเส้นทางและเวลา ICT |
| `track-state.json` | เก็บรหัส track เพื่อเชื่อมรอบถัดไปผ่านภาพที่ซ้ำกัน |
| `download-manifest.json` | แหล่งที่มา เวลา และ SHA-256 ของภาพที่ดาวน์โหลด/กู้จาก artifact |
| `analysis-manifest.json` | ภาพที่ใช้จริง พร้อม SHA-256 และเวอร์ชัน model/config |
| `*dBZ.cappi.png` | ภาพต้นฉบับไม่เกิน 10 ภาพ |

สำหรับ consumer ให้เริ่มอ่าน `user_summary` ใน JSON: `status`, `message_th`, `freshness`, `target_echo`, `forecast`, และ `data_quality` เป็นชุดข้อมูลสรุปสำหรับแสดงต่อผู้ใช้ ส่วน `target_echo.state` ที่เป็น `unknown` หมายถึงพื้นที่เป้าหมายมีพิกเซลที่แปลผลได้ไม่พอ ไม่ใช่ “ไม่มีฝน”; `forecast.available` ที่เป็น `false` หมายถึงยังไม่ควรแสดง ETA

`model_eta_min_at_scan` ในตารางประวัติเป็นผลคำนวณย้อนหลังในชุดข้อมูลนั้น ไม่ใช่รายการแจ้งเตือนที่เคยส่งจริง

### การอ่านสถานะ

| สถานะ | ความหมาย |
|---|---|
| `inbound_echo` ใน JSON / `inbound` ใน CSV | แนวรูปร่างกลุ่ม echo ตัดช่องเป้าหมายภายใน 60 นาที และผ่านการตรวจความต่อเนื่อง |
| `echo_at_target` | มีกลุ่ม echo ≥20 dBZ ที่ผ่านเกณฑ์ขนาดแตะช่องเป้าหมายในภาพนั้น |
| `approaching_outside_horizon` | แนวคาดการณ์อาจตัดเป้าหมายหลัง 60 นาที จึงไม่ให้ ETA ระยะไกล |
| `passing_target` / `moving_away` | เส้นทางตามความเร็วที่ประมาณได้ไม่ตัดพื้นที่เป้าหมาย |
| `uncertain_motion` | การจับคู่ รูปร่าง หรือแนวการเคลื่อนที่ยังไม่ชัดเจน |
| `building_track` | ยังมีภาพต่อเนื่องของกลุ่มนั้นไม่ถึง 3 ภาพ |
| `ended` | ไม่พบ track นี้ในภาพล่าสุด; ไม่ให้ ETA ปัจจุบัน |
| `insufficient_data` / `stale_data` | ภาพไม่ครบ/ขาดช่วง/เวลาอนาคต หรือภาพล่าสุดเก่าเกิน 18 นาที; งด forecast |
| `no_confirmed_inbound_echo` | ยังไม่พบกลุ่มที่ผ่านเกณฑ์ inbound; **ไม่ได้หมายความว่าจะไม่มีฝนแน่นอน** |

`speed_kmh` คือความเร็วการเคลื่อนที่ของจุดศูนย์กลางกลุ่ม ส่วน `closing_speed_kmh` คือองค์ประกอบของความเร็วนั้นเข้าหาเป้าหมาย ไม่ใช่ความเร็วลม

## วิธีคำนวณ

1. ตรวจว่า PNG เปิดและถอดรหัสได้ ขนาด 1076 × 800 และแถบสีตรงกับ calibration ที่ตั้งไว้
2. จับคู่ RGB ตรงกัน แปลงสีเป็นช่วง dBZ โดยอ้างอิง **ตำแหน่งขอบเกณฑ์ใน legend** ค่าสีระหว่างตัวเลขเป็นการประมาณ; เก็บค่าต่ำ/สูงของช่วงไว้
3. ตัดสีขาวออกจากการตีความ เพราะแยกตัวหนังสือกับ echo สีขาวรุนแรงมากจาก PNG นี้ไม่ได้ พิกเซลที่ถอดค่าไม่ได้ถือว่า **unclassified** ไม่ใช่ 0 dBZ และไม่ลบ echo สีอื่นเพียงเพราะอยู่นิ่ง
4. จัดกลุ่ม 8-connected โดยใช้ค่าต่ำของช่วง dBZ ≥20 และอย่างน้อย 5 pixels
5. จับคู่กลุ่มระหว่างภาพด้วย global assignment โดยดูตำแหน่งที่คาดจากการเคลื่อนที่, shape overlap และอัตราการเปลี่ยนขนาด พร้อมทำเครื่องหมายกรณีคลุมเครือ/อาจแยกหรือรวมกลุ่ม
6. ใช้ regression จาก 3–5 ภาพต่อเนื่องกับเวลาจริงเพื่อประมาณเวกเตอร์ความเร็ว ถ้าไม่ต่อเนื่อง จับคู่ไม่ชัดเจน หรือ residual สูง จะไม่ออก ETA
7. เลื่อน **รูปร่าง pixel ทั้งกลุ่ม** ตามเวกเตอร์ดังกล่าว แล้วหาเวลาที่ขอบรูปร่างตัดสี่เหลี่ยม SBM-2 ต้องมีแนวขอบกลุ่มเข้าใกล้สอดคล้องกันด้วย
8. เผยผล forecast เฉพาะภาพล่าสุด เมื่อมี 10 ภาพต่อเนื่องและข้อมูลไม่เก่าเกินเกณฑ์

ID ของกลุ่มใช้ภาพ/รูปร่างที่ซ้ำกันกับ artifact ก่อนหน้าเพื่อเชื่อมรอบ การเปลี่ยน model/config, ไม่มีภาพซ้อนทับ หรือกู้ state ไม่ได้ จะเริ่ม ID ใหม่ การจับคู่ยังอาจผิดได้ จึงมี `identity_conflict`, `match_ambiguous` และ `possible_split_or_merge` ให้ตรวจ

## การดาวน์โหลดและการเก็บข้อมูล

- API: `https://file.royalrain.go.th/opendata/radar_data/cappi/api.php?station=sattahip`
- Timeout ต่อคำขอ: connect 20 วินาที / รวม 120 วินาที ทั้ง API และ PNG; ลองสูงสุด 3 ครั้ง
- ดาวน์โหลดพร้อมกันสูงสุด 2 ภาพ; ใช้ภาพเดิมที่ตรวจแล้ว และโหลด 2 ภาพล่าสุดใหม่เผื่อต้นทางแก้ไข
- ใช้ HTTPS เฉพาะ host/path ของสัตหีบที่กำหนด; ปฏิเสธ redirect และไฟล์เกิน 16 MiB
- ดาวน์โหลดลง staging ก่อน ตรวจครบแล้วค่อยแทนชุดเดิม
- Cold start หลังเที่ยงคืนที่ยังมีไม่ถึง 10 ภาพจะเป็น `insufficient_data` และเก็บภาพสะสมไว้
- Artifact เก่าใช้ได้ 2 วันถ้าไม่มีรอบใหม่; เมื่ออัปโหลดชุดใหม่สำเร็จจึงลบ artifact เก่าของ workflow/branch นี้ ชื่อ artifact แยกตาม run/attempt เพื่อไม่ลบชุดเดิมก่อน rerun อัปโหลดสำเร็จ
- รัน pipeline ทีละชุดด้วย concurrency lock; การลบ artifact ล้มเหลวจะเตือนใน log และเก็บชุดใหม่ไว้
- รับ artifact ชื่อเดิม `sattahip-radar-latest-10` ได้เพื่ออัปเกรดจากเวอร์ชันแรก

## รันบนเครื่อง

ต้องมี Python 3.12 และ `curl`; `gh` จำเป็นเฉพาะขั้น restore/prune บน GitHub

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/download_radar.py
python scripts/analyze_radar.py
```

ทดสอบภาพย้อนหลังโดยระบุเวลาตรวจสอบที่มี timezone ชัดเจน ผลจะติด `mode: historical_replay`:

```bash
python scripts/analyze_radar.py --image-dir radar_images --as-of 2026-09-27T01:00:00+07:00
```

ค่าปรับทั้งหมดอยู่ใน `config/radar.json` อย่าเปลี่ยนเวลาในชื่อไฟล์ให้เป็น ICT เอง

## ก่อนนำผลไปใช้เตือนผู้ปฏิบัติงาน

- ยืนยัน projection, จุดศูนย์กลางเรดาร์, pixel ของ SBM-2 และสเกล 0.6 กม./pixel กับเจ้าของข้อมูล ปัจจุบันใช้ calibration จากภาพและ `georeferencing_verified: false`
- dBZ จาก PNG เป็นค่าประมาณ ไม่ใช่ข้อมูลเรดาร์ดิบ และไม่ได้แปลงเป็น mm/h
- ภาพ PCAPPI/echo ระดับสูงไม่ยืนยันฝนที่พื้น ฟ้าผ่า ลมกระโชก หรือคลื่น
- เก็บเหตุการณ์ย้อนหลังหลายแบบ พร้อมฝนจริงที่ SBM-2 เพื่อวัด missed events, false alarms และความคลาดเคลื่อน ETA ในช่วง 0–60 นาที
- ทดสอบกลุ่มฝนแยก/รวม ก่อตัว/สลาย และ source ล่ม; โมเดลปัจจุบันสมมติการเคลื่อนที่คงที่และไม่พยากรณ์การก่อตัวใหม่
- ตรวจ `valid_until_ict` ทุกครั้งที่อ่าน Public API; ค่าที่หมดอายุให้แสดงเป็นข้อมูลเก่าและงดข้อความคาดการณ์
